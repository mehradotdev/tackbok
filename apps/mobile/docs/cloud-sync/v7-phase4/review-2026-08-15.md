## Entry obligations

- **Y1 discharged.** Destructive probe helpers (`createPhysicalHeadForProbe`,
  `createRevocationForProbe`, `deleteAllForProbe`, `setCursorForProbe`) now
  require `__DEV__ && enableDevProbeMethods === true` at construction and
  assert that flag as their first statement, before any request. The
  production engine and every production UI path construct the provider
  without the option; the probe runner alone passes it. A regression proves
  the helpers throw on an ordinary instance. The two genuinely production
  methods added in this round — `publishRevocation` and `purgeRevokedVault` —
  are deliberate user-facing deletion features, reachable only through
  `revokeCloudVault`, which records the revocation marker first and pauses
  with `purge-incomplete` if the purge cannot prove zero remaining objects.
- **Y2 discharged.** `MAX_DISCOVERY_REBUILDS = 1`; a second cursor rejection
  after a fresh rebuild returns a transient provider error instead of
  recursing. The fake-server regression observes exactly two start-token and
  two changes requests before the bounded stop.

## Production data path review

- **Capture** reads the complete normalized journal inside one transaction,
  refuses to run without initialized v2 state, sorts deterministically, and
  excludes the local profile email from the snapshot domain.
- **Apply** is a generation-CAS complete-state replacement: it re-checks
  `journal_generation` inside the transaction, preserves the prior local
  email, retains every replaced media file in the retained-media ledger with a
  completed obligation before deleting its normalized row, preserves conflict
  acknowledgement state across re-application, and leaves file deletion to
  the established reaper. Media materialized before a failed CAS is reused by
  the idempotent staged-file path on the retried apply.
- **Mutation routing** advances the v2 journal generation in the same
  transaction as every routed entry/tag/prompt/profile mutation, records
  tombstones with a canonical deleted-state hash on delete, and removes the
  tombstone on recreate. The v1 queue path is untouched below the v2
  early-return. The offline-durability gate test proves
  `journalGeneration=1, settledGeneration=0` survives state reconstruction.
- **Protocol selection**: `protocol_version` has existed since migration 0004
  with default 1. Existing vaults construct the v1 runtime unchanged; only
  `completeGoogleDriveConnection` writes `protocol_version: 2`, with fresh v2
  state and no v1 head/cursor/object import. Migration 0010 completes the
  domain (v2 tombstones, exact conflict envelopes, entry
  `conflict_origin_id`; tags/prompts had the column since 0004), and the gate
  applies migrations 0000–0010 to fresh SQLite to prove it.

## Runtime and UI review

- Foreground drain uses `hasPendingWork()` through the runtime's re-run
  trigger; the gate observes four injected units → four passes → zero work.
  Background invocations pass `allowFollowup: false` and run exactly one
  bounded pass. An attention/retry failure throws, so a durable blocker can
  never report success — and cannot re-trigger the drain loop.

  All 20 ADR V7-0004 attention reasons map to a stable recovery-action ID and
  localized plain-language copy in all six locales, with alert/live-region
  semantics; the gate asserts the full 20×screen and locale coverage.

  filters probe vaults. Onboarding restore reuses the same prepared-connection
  flow without historical-restore UI.
- The journal-wipe path now also deletes the v2 shadow/staging directories

  synchronized. The public policy paragraph is plain-language, names no
