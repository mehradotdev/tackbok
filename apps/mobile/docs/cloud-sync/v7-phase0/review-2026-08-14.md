# Owner review of Phase V7-0 — 2026-08-14

Independent review of the V7-0 design bundle. Every executable claim was
re-run rather than accepted from the implementation report.

Verdict: **bundle verified. §18.5, §18.6, and §18.10 are closed under the
owner's delegated approval recorded in plan-v7 §18. V7-1 is authorized with
one carried obligation (V1 below).**

## Re-verification

- `bun run v7:phase0:test`: 24/24 green, re-run at review.
- **Non-circular canonicalization check:** a from-scratch Python
  canonicalizer written only from ADR V7-0002's prose (UTF-16 code-unit key
  order, JSON.stringify-style escaping, integer emission) reproduced all
  8 accepted vectors byte-identically and hash-identically. The fixture is
  not merely self-consistent with the TypeScript canonicalizer that
  generated it.
- The `utf16-object-key-order` vector genuinely distinguishes UTF-16
  code-unit order from code-point order (U+1F600 before U+E000); the frozen
  fixtures would catch a runtime that sorts by code point.
- U+2028/U+2029 are present in the frozen fixture as ADR V7-0002 claims.
- Both measurements re-run **byte-for-byte identical** to the recorded
  reports (2,329,562 / 307,027 and 11,631,139 / 1,518,981 bytes); timings
  within noise. The measurement tool retains no user data and honestly
  labels its memory numbers as host-only.
- Merge golden catalog spot-checks match ADR V7-0003 (delete-vs-rename with
  concurrent new reference preserves the tag and writes both `deleteEdit`
  and `referencedDelete`; the unreadable-base case has `base: null` and a
  conservative expected output). Conflict IDs in every expected output
  re-derive from the documented formula (verified by the suite).
- ADR V7-0006's Google quota figures were checked against the live Drive
  documentation at review time: 325,000 units/min/user, reads 5, lists 100,
  downloads 200, edits 50, truncated exponential backoff for 403/429 — all
  correct as cited.
- `bun x tsc --noEmit` clean; full Jest suite 42 suites / 378 tests green.
- Scope audit confirmed: no `src/` change; `src/lib/cloudSync/protocol/`,
  `phase0/`, and `phase3/` untouched since `f296f56`; only
  `docs/cloud-sync/v7-phase0/`, the docs README, and non-production
  `package.json` scripts changed.

## Findings

- **V1 — device evidence is not reproducible (obligation carried into
  V7-1).** The Android API 36.1 and iOS 26.5 canonical-vector reports state
  they were executed "through a temporary dev-only import that was removed
  after capture." There is no code path in the repository that can re-run
  them, which departs from the phase0/phase3 convention that evidence
  harnesses are kept executable. The review therefore treats those two
  reports as **attested, not verified**. Obligation: V7-1 must wire
  `tools/deviceFixtureProbe.ts` (or a successor) into the `__DEV__`
  dev-diagnostics route permanently and re-capture both platform reports
  through that durable path before the V7-1 gate relies on cross-runtime
  determinism.
- **V2 — hand-wrapped report envelopes (minor).** The evidence JSONs carry
  fields (`executedAt`, `scope`, `runtimeVersion`, redaction attestations)
  that the probe's `V7CanonicalDeviceReport` type does not produce, so the
  files were assembled by hand around the probe result. When V1 is done,
  the probe should emit the complete report shape itself and pass it
  through an `assertReportIsRedacted`-style check, as phase3 probes do.

## Decisions recorded at this review

- **§18.5 closed:** the 16 MiB compressed / 64 MiB uncompressed envelope
  and the ADR V7-0001 cap table are approved as protocol-v2 candidate
  limits, supported by the measured 10,000-entry journal at 9.1% of the
  compressed cap.
- **§18.6 closed:** the ADR V7-0003 merge table and the frozen golden
  catalog are approved. V7-1 implements these outcomes; a fixture may
  change only through a recorded ADR amendment with owner sign-off, never
  to make code pass.
- **§18.10 closed:** the ADR V7-0006 logical-request ceilings and the
  candidate physical-device targets in `measurements/README.md` are
  approved as the numeric targets that V7-3 (requests) and V7-5 (device
  performance) gates must meet or formally reopen.
