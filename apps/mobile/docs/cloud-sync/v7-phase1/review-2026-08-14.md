## ADR V7-0007 forensic affirmation

The amendment's account was verified against git history, not taken on
trust:

- The fixture as committed in `07e521c` is internally inconsistent: the
  `controls-and-line-separators` vector records SHA-256 `acecb51c…` while
  its committed canonical bytes hash to `3b7167e7…`, and U+2028/U+2029 are
  absent.
- The amended vector's canonical bytes hash to exactly the pre-existing
  recorded `acecb51c…` — the hash the V7-0 owner review independently
  verified byte-for-byte before the commit. The full value therefore
  existed at review time; the truncation entered at commit time (raw
  line-separator characters mangled in the committing environment).
- Only that vector's `value`/`canonical` changed. Every other vector, every
  recorded hash, and the entire reject list are byte-identical to the
  committed fixture.

This is a restoration of signed-off content, not a change to make code
pass. It sets no precedent: fixture changes still require a recorded ADR
amendment with owner sign-off.

## Findings

- **W1 — merge can emit an unencodable domain (obligation carried into
  V7-2).** If one branch deletes an entry that is unchanged from base (so
  the deletion wins and the branch's snapshot validly omits the entry's
  media) while the other branch concurrently updates only an observed
  media field (for example `width`), `mergeSnapshotDomainsV2` keeps the
  updated media descriptor while tombstoning its owner. The merged domain
  then fails the codec's own referential validation ("Invalid media owner")
  and cannot be encoded. Reproduced at review against the real
  implementation. This is fail-closed — no data loss or corruption — but a
  legitimate concurrent pair wedges publishing. Obligation: fix (drop or
  conflict-record media whose merged owner is tombstoned) with a
  regression test before any V7-2 code consumes `mergeSnapshotDomainsV2`
  output.
- **W2 — tombstone provenance is argument-order dependent (recorded,
  minor).** With equal `deletionSequence` and compatible hashes,
  `chooseTombstone` keeps the first argument's `deletedByDeviceId`, so two
  devices merging the same pair converge to content-equal but
  byte-different snapshots. This sits outside the gate's scoped
  commutativity claim (user state and conflict candidates, which were
  verified order-free) and per-device heads make byte divergence
  harmless, but a deterministic provenance tie-break would improve
  convergence. Optional.
- **W3 — empty `mimeType` bypasses the printable-ASCII check (nit).**
  `validation.ts` short-circuits on the empty string, so
  `mimeType: ""` is accepted. Cosmetic; tighten when the file is next
  touched.
